# DSH Links RC1 封闭 Beta 测试包

本包面向 3–5 名相互独立的测试者。它是测试执行材料，不是公开 Relay
发布说明。公开支持路径仍是同一可信局域网；Relay 为维护者接入码私测。

## 测试前发放清单

维护者逐人发放：

1. 指定版本的官方签名 Android APK、版本号和 SHA-256；测试者不得安装重打包 APK。
2. 已锁定的插件/Relay revision 和 DSH 兼容版本，见 RC1 证据记录；不要使用 moving `main`。
3. 一次性、单人接入信息。接入码、云端二维码、`routeSecret`、Token、私钥不得出现在聊天、截图、录屏或反馈正文。
4. 本包、反馈模板和事故模板；测试者先阅读“停止条件”。

维护者保留一份逐人发放记录，但不把接入码或任何凭据写入仓库。

## 独立 onboarding（每人从零开始）

1. 在可信 LAN 中启动 DSH 和插件，确认电脑端显示手机连接二维码/配对码。
2. 安装并校验 APK，扫码配对，完成一次历史读取、发送消息、接收 SSE 事件和审批操作。
3. 关闭 App、重启 DSH，再打开 App，确认设备仍能连接；在电脑端吊销该手机并确认后续请求为未授权。
4. 如被安排 Relay 私测，使用维护者单独发放的接入信息完成一次 Host Enrollment 和云端扫码；确认 LAN 与 Relay 是两个独立入口。
5. 记录开始时间、首次成功连接时间、设备/系统版本、测试 revision 和结果；不得记录消息正文或凭据。

目标：每名测试者首次连接在 10 分钟内完成；遇到失败先保存脱敏诊断，再按事故模板报告，不要反复重配导致证据丢失。

## 必做任务脚本

- T1 配对与回收：扫码、手动输入、重启、移除、重新配对各一次。
- T2 会话边界：打开空历史、至少 30 条历史、长消息、SSE 断网/恢复、App 后台再前台。
- T3 真实工作流：新建会话、继续会话、工具/审批成功与超时、切换工作区；不得把“页面打开”算作成功。
- T4 认证与撤销：错误配对码、重复配对、电脑端吊销手机、Relay Host 吊销、旧连接恢复；确认没有越权或跨 Host 数据。
- T5 Relay 重连（仅私测人员）：电脑和手机分别重启、Relay 重启、断网 60 秒后恢复、旧 enrollment 失效后重新 enrollment；每个结果带时间戳。
- T6 运维演练（维护者执行并邀请观察）：备份/恢复、证书轮换、Control/Relay 重启、吊销和回滚；测试者只确认用户可见结果。

每个任务填写：前置条件、动作、预期、实际、是否通过、脱敏诊断文件名。不要以单元测试或主机模拟替代真实 Android→Relay→Plugin 链路。

立即停止并通知维护者：看到另一 Host/用户数据、Token/routeSecret/私钥出现在日志或诊断、吊销后仍可访问、重复配对绕过确认、连接重试造成跨 Host 串线、消息/文件丢失且无法确认边界、证书指纹不匹配仍建立连接、或任何无法解释的凭据泄露。不要继续扩大测试、不要删除状态、不要把截图发到公开渠道。

## RC1 退出标准

测试窗口至少 7 天，且满足全部硬门槛：

- 至少 4/5 名独立测试者完成 onboarding；每人首次成功连接 <10 分钟。
- 至少 30 次真实远程会话（若 Relay 未开放给该批，则明确记录未满足，不得用模拟数替代）。
- 零越权、跨 Host 串线、数据丢失、凭据泄露；零重复配对绕过和重连阻断。
- 认证、撤销、重启、重新 enrollment、证书轮换、备份恢复运维演练均有可追溯结果。
- 诊断足够定位失败，且脱敏测试确认不含 Token、`routeSecret`、邀请码、私钥、明文凭据或消息正文。
- 三仓 CI、DLR/1 一致性门禁和本地高价值测试全绿；真实 Android→Relay→Plugin、真实公网 CA/TLS、24h soak、容量测量分别有证据，未验证项保持未验证。

任一硬门槛失败，RC1 不能退出封闭测试；修复后重新计数，不得用“总体感觉稳定”覆盖缺失证据。
