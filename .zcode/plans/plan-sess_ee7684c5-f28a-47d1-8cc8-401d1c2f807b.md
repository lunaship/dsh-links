## beautifului.dev 借鉴 · DeepHarness 实现计划（4 项）

### 决策摘要

| 项目 | 决策 |
|---|---|
| **Selection Actions** | UI + 改插件透传 `kind` + `selection` 字段到 `session.prompt` |
| **Tool Chips 聚合** | 连续 ≥2 条 tool_call/tool_result 聚合成"X 个工具调用 · 展开/收起"，默认收起 |
| **Dots Loader 变体** | 新增 `RunningDots()` 替换 CommandCard running 态的 `RunningSweep()`（不动 ReasoningRow / TurnStatusRow）|

## 1. Selection Actions（长按选中文本 → 弹 5 个改写胶囊）

**目标**：用户长按 assistant 消息中的某段文本 → 系统选区手柄出现 → 文本上方浮出 5 个胶囊按钮（Explain / Improve / Shorten / Tone / Grammar）→ 点击胶囊把选区提交到 DSH 作为改写任务。

**涉及改动**：

### 1.1 前端 UI（WorkspaceActivity.kt）

- **新增**：在 DshIcons.kt 添加 5 个 outline 矢量图标 `RewriteExplainOutline16` / `RewriteImproveOutline16` / `RewriteShortenOutline16` / `RewriteToneOutline16` / `RewriteGrammarOutline16`（参考现有 `BranchOutline16` 路径风格，圆角线性图标）
- **重构 MessageItem**（4389-4460）：
  - **拆掉**当前 `combinedClickable.onLongClick` ——它会吞掉系统文本选择
  - **新增长按事件分离逻辑**：使用 `pointerInput { detectTapGestures(onLongPress = { offset -> menuOpen = true })` 仅在**非文本位置**触发原菜单（仍然打开"复制/引用/分叉"）；选区由 SelectionContainer 自然处理
  - **包 `AssistantMarkdown`**：用 `SelectionContainer` + `selectionState = rememberTextSelectionState()` 包裹（导入 `androidx.compose.foundation.text.selection.*`）
  - **新增 SelectionActionsBar composable**（约 70 行）：
    - 参数 `selection: TextRange`、`actions: List<SelectionAction>`、`onAction: (kind: String) -> Unit`
    - 视觉：胶囊容器 `Dsh.bgLayer1` 12dp 圆角 + 1dp `borderL2` + 12dp shadowElevation
    - 每个胶囊：图标 16dp + label 13sp（labelSecondary），padding 10/8，按下 bgNavActive
    - **5 个 action**：`Explain` / `Improve` / `Shorten` / `Tone` / `Grammar`
    - **定位**：固定浮在消息顶部（`Modifier.align(Alignment.TopCenter)`），不精确跟随选区手柄（避免 offset 边界问题；移动端 UX 友好）
    - **出现条件**：`selection.length > 0` && `role == "assistant"`（user/assistant 文本可选，但改写只对 assistant）
  - **修改 DshMenuItem**（2922-2927）：增加可选 `iconTint: Color? = null`、`secondary: Boolean = false` 字段（兼容现有调用点，不破坏签名）
- **重构 AssistantMarkdown**（4891-4898）：
  - 移除外层 `longPress` modifier（现在走 SelectionContainer 链路）
  - 把 `MarkdownContent` 整段包进 `SelectionContainer(selectionState = selectionState)`
- **新增 onSelectionAction 回调**：从 WorkspaceScreen 传入：
  - 把 `selectionText + kind` 编码成 `MobileSelectionRewrite(text = originalText, selectionStart, selectionEnd, kind)` 数据类
  - 调用 `MobileApi.sendRewritePrompt(sessionId, payload)` 新方法
  - 成功后关闭选区、清空 selectionState、Toast "已提交改写"
- **保留原"复制整条"长按菜单**：SelectionContainer 不影响 Box 外层手势，`pointerInput` 仍然响应非选区位置的长按

### 1.2 后端字段透传（dsh-deepharness 插件）

- **改 `MobileApi.sendPrompt`**（MobileApi.kt 303-316）：增加 `kind: String? = null`、`selection: Pair<Int, Int>? = null` 可选参数；JSON payload 同步加 `kind` / `selection: [start, end]`
- **新增 `MobileApi.sendRewritePrompt`**：转发到同一 `/prompt` 端点，payload 携带 `kind = "rewrite"`, `selection = (start, end)`, `text = originalMessageText`
- **改 `dsh-deepharness/src/index.js:769-791`**：
  - 解构 `body.kind` / `body.selection`
  - 在 `content` 数组里**插入一个特殊 text 块**：当 `kind === "rewrite"` 时，按格式 `"\n[rewrite:${kind}] ${selection[0]}-${selection[1]}: ${fullText}"` 推入（最简实现：把整条原文带上 selection range 一起喂给 DSH，由 DSH 端自行处理）
  - 透传到 `session.prompt` RPC：`callLocalRpc(targetPort, "session.prompt", { sessionId, mode, content })`
- **改 `build-client.mjs`**（如果有 client 透传需求）：检查文件确认是否需要同步——如果只是 server 端注入，client bundle 不需要改
- **重启 dsh web**（你手动执行，遵循 `dsh-server-infra.md` 重启流程）

### 1.3 风险与回退

- **SelectionContainer 与 combinedClickable 冲突**：必须拆掉原有 long-press，否则系统选区手柄不会出现。已识别且有明确重构方案
- **MarkdownContent 块级渲染**：每个 block 是独立 `Text`，SelectionContainer 能跨 block 选区（基于底层 AnnotatedString 拼接）。需要实测长代码块/表格/链接的选区连续性
- **后端不可用降级**：若 `kind` 字段未被服务端识别，至少文本能被正确发送，不会崩溃
- **范围限制**：仅对 `assistant` / `user` role 起作用；reasoning / tool_call / tool_result / todo 不进入改写

## 2. Tool Chips 聚合（聊天视图）

**目标**：5 个连续 tool_call + tool_result 当前展开为 10 个 LazyColumn item；聚合后变成"X 工具 · +Y.Ys · 收起/展开"一行 + 默认收起的下挂卡片。

### 2.1 数据切分（WorkspaceScreen，1598-1650 行）

- **新增工具函数** `groupMessages(messages: List<MobileMessage>): List<MessageGroup>`：
  - 类型 `MessageGroup = UserGroup(msg) | AssistantGroup(text+reasoning) | ToolGroup(items: List<MobileMessage>) | SingleGroup(msg)`
  - 算法：`messages.fold` 时遇到连续 `role ∈ {tool_call, tool_result}` 累积进当前 `ToolGroup`，遇到非 tool role 收尾
  - **聚合触发条件**：`ToolGroup.items.size >= 2`（阈值≥2，与决策一致）；< 2 时退化为 `SingleGroup` 平铺
- **LazyColumn 改造**：用 `items(groups, key = { groupId(it) })` 替换 `items(allMessages, key = { it.id })`
  - `groupId()` 策略：ToolGroup 用首条 id + "-group"；其他用 `msg.id`

### 2.2 聚合 header composable（新增，约 80 行）

- **位置**：插在 `MessageItem` 调用前（约 1600 行）
- **函数名** `ToolGroupHeader(group: ToolGroup)`
- **视觉**：
  - 容器：`Modifier.fillMaxWidth().clip(RoundedCornerShape(12.dp)).background(Dsh.bgCode).border(1.dp, Dsh.borderL1, 12dp)`
  - Header Row：左侧 4dp 圆点（CommandCard 同款）+ "X 工具调用" 14sp/24sp + `weight(1f)` + "+Y.Ys" 等宽 11sp labelCaption（从 group.items 取 time 差） + chevron icon
  - 内容：AnimatedVisibility 包裹下挂 `group.items.map { CommandCard(...) }`
- **折叠状态**：`var expanded by remember { mutableStateOf(false) }` 默认收起
- **入场动画**：继承 LazyColumn item 已有的 `animateItem()`，不需新增
- **样式参照**：复用 `RunningSweep()` 不用（聚合组没 running 概念——单条 tool 自己的 running 视觉仍在 CommandCard 内部）

### 2.3 MessageItem 调用调整（4389 行）

- **新增分支**：`MessageItem` 不需要改 if role==tool_call/tool_result 的渲染（保留原样），因为聚合在 LazyColumn 层做，group 渲染时仍调用 MessageItem
- **实际调整**：把 `items(allMessages)` 替换为 `items(groups)` 后，渲染处加一个 `when (group)` 分支（与 MessageItem 共存）

### 2.4 风险

- **流式增量不会改变相邻性**：`toolCallTimes` / `streamToolCallIds` 在 append 时维持顺序，group 算法纯客户端
- **翻页**：olderMessages + messages 拼接在 1541 行，groups 算法对全列表跑一次即可
- **入场动画**：聚合组的展开/收起用 `AnimatedVisibility` 内部 `expandVertically` + `fadeIn`（参考 ReasoningRow 模式）
- **回退**：保留 `SingleGroup` 退化路径，≤1 条 tool 时与现状完全一致

## 3. Dots Loader 变体

**目标**：CommandCard running 态从 sweep 扫光改为 3 个脉动点，更轻量、更移动端友好。

### 3.1 新增原语（DshMotion.kt，追加在 79 行后）

```kotlin
/**
 * 3 个脉动点的进度值（alpha 0.3→1→0.3）。
 * 返回 [Float?; 3]，reduce-motion 时全部为 1f（静态满 alpha）。
 */
@Composable
fun rememberMotionDots(count: Int = 3, periodMs: Int = 900): List<Float> {
    val reduce = isReduceMotionEnabled()
    val transition = rememberInfiniteTransition(label = "dots")
    return (0 until count).map { i ->
        transition.animateFloat(
            initialValue = 0.3f,
            targetValue = 1f,
            animationSpec = infiniteRepeatable(
                animation = tween(periodMs, easing = LinearEasing, delayMillis = i * 150),
                repeatMode = RepeatMode.Reverse
            ),
            label = "dot-$i"
        ).value.also { if (reduce) it }
    }
}

/** 3 个 4dp 圆点，alpha 由 rememberMotionDots 驱动。reduce-motion 时静态全亮。*/
@Composable
fun RunningDots(tint: Color = Dsh.brand400) {
    val alphas = rememberMotionDots(count = 3, periodMs = 900)
    Row(verticalAlignment = Alignment.CenterVertically, horizontalArrangement = Arrangement.spacedBy(3.dp)) {
        alphas.forEach { a ->
            Box(Modifier.size(4.dp).clip(CircleShape).background(tint.copy(alpha = a)))
        }
    }
}
```

### 3.2 替换 CommandCard running 视觉（5441-5516 行）

- 当前 5513-5514 行 `if (running) RunningSweep()` **改为** `if (running) Row { Text(runningLabel); Spacer(8.dp); RunningDots() }` 放在 header Row 内（替换原 runningLabel 单独 Text）
- ReasoningRow / TurnStatusRow **不动**：它们的扫光/文本 shimmer 各有视觉优势

### 3.3 风险

- 仅 1 处 composable 内部替换，1 个新原语
- 零后端依赖、零数据模型改动

## 4. Filter chip（侧栏会话列表）

**目标**：侧栏会话列表顶部加 3 个状态过滤 chip，与现有 flatView toggle 共存。

### 4.1 数据判定（0 后端改动）

- **状态映射**：
  - "全部" = 全部 sessions
  - "运行中" = `session.running == true`
  - "已停止" = `!session.running && !session.blank`（即有过消息的非运行中会话，含已完成 + 已失败，统一归"已停止"——决策一致）
- **过滤实现**：`val filteredSessions = sessions.filter { ... }` 在 WorkspaceScreen 内部派生
- **blank 会话**：全部 / 已停止 chip 都**包含** blank（空白会话本身就在侧栏显示）

### 4.2 新增 SessionFilterChips composable（约 50 行）

- **位置**：插入侧栏 LazyColumn 上方（约 987 行），flatView toggle 行下方
- **参数**：`selected: SessionFilter`、`onSelect: (SessionFilter) -> Unit`、`counts: Map<SessionFilter, Int>`
- **视觉**：横向 Row，3 个 chip，间距 4dp，左对齐，水平 padding 8dp
  - 每个 chip：`Modifier.height(28.dp).clip(999.dp).background(if selected Dsh.bgNavActive else Color.Transparent).clickable {...}.padding(horizontal = 12.dp)`
  - 文字："全部 12" / "运行中 3" / "已停止 9"，格式：label + 空格 + count，13sp/500，selected 用 labelPrimary，未选用 labelSecondary
- **样式参考**：完全复用 ModeChip（2489-2516）的视觉与点击反馈，**抽出通用组件** `DshFilterChip(label, selected, onClick)` 放 DshTheme.kt 末尾
- **可选扩展**：为了支持未来 4 个 chip 状态，定义 `enum class SessionFilter { ALL, RUNNING, STOPPED }`

### 4.3 接入侧栏（862-1193 行）

- **WorkspaceScreen 顶层 state**：`var sessionFilter by remember { mutableStateOf(SessionFilter.ALL) }`
- **侧栏 LazyColumn 数据源**：`val visibleSessions = sessions.filter { matchesFilter(it, sessionFilter) }`，把现有 `visibleSessions`（993/1034 行）替换为过滤后版本
- **counts 计算**：`val counts = remember(sessions) { sessions.groupingBy { classify(it) }.eachCount() }`
- **不破坏**：工作区分组（`groupBy`）、子智能体过滤、blank 24h 隐藏等现有逻辑

### 4.4 风险

- 数据完全本地判定，零后端依赖
- 与现有 flatView toggle 共存无冲突
- 切会话时 `sessionFilter = ALL` 复位（避免上个会话的过滤遗留）
